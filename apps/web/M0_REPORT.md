# D3 报告：形象渲染

查看时间：2026-11-16 晚，新加坡时间。演示在本机 `http://127.0.0.1:5173/`。

## 模型和许可

用的是 VRoid Studio β 的官方示例 **Vita**（β Ver AvatarSample_3）。

- 作者：pixiv Inc.
- 许可：CC0。说明见 `public/models/SOURCE.md`。
- 文件：`madjin/vrm-samples` 里的 `vroid/beta/Vita.vrm`，约 14MB，运行 `pnpm download:vrm` 获取，不入库。
- 格式：文件里的扩展是 `VRM`，不是 `VRMC_vrm`。这是 **VRM 0.x**，不是任务单写的 VRM 1.0。

同一角色的 VRM 1.0 转换件在 VRoid Hub 上，没有不登录就能下载的稳定地址，所以演示用这份 CC0 原件。`three-vrm` 3.5 两种都加载。若以后把 1.0 文件放到 `public/models/avatar.vrm`，同一页会按 `metaVersion` 处理，0.x 会做坐标系旋转，1.0 不会。

这不是克劳德。正式模型还没到，这里只看渲染、待机和口型。

## 这台机器上的帧率

| 项 | 读数 |
|---|---|
| 渲染器 | `WebKit WebGL` |
| 帧率 | 观察时大约 9 fps |
| 帧耗时 | 大约 117 ms |
| 像素比 | 页面把 `devicePixelRatio` 限制为 1 |
| 抗锯齿 | 开着 |

控制台有软件 WebGL 的弃用提示，以及截图回读造成的 `ReadPixels` 停顿。这台云主机没有独立显卡，也不是集成显卡笔记本，更不是手机。

任务单要的两档——集成显卡笔记本 ≥ 60 fps、手机 ≥ 30 fps——**这次没有测到**。不能把 9 fps 写成那两档的结果，也不能反过来写成“达不到”。在普通笔记本上打开同一页之前，这两条验收是空的。

## 看到的画面

- 全身在画面里，头到脚，深色渐变背景，没有洋红丢材质。
- 原文件是 T 字站姿。归一化骨骼的静止姿态就是这个 T 字。页面用程序把上臂放下、小臂略弯，这是每帧算的站姿，不是动画片段。
- 待机没有循环片段：呼吸周期每次重新抽，眨眼间隔 2–6 秒，大约一成会连眨，重心每 8–20 秒换一次。30 秒的录屏里看不到一个重复点；60 秒是否仍看不出循环，要有人盯着看，程序本身没有循环点。
- 鼠标带动视线。眼睛先动，头和颈随后，幅度有上限。观察时没有眼球翻白，也没有头一下子拧过去。
- 口型：音频驱动时能量高会张到 `aa`，并叠一点当前元音；时间轴模式按 `public/lipsync/demo-timeline.json` 走，那份时间轴是示意，**不是供应商音素**。把脸放大后能看出闭嘴、圆唇和张嘴的差别。全身构图里嘴很小，差别变弱。D2 里 MiniMax 和 CosyVoice 都带回了字级时间戳，豆包合成 2.0 后来也带回了字级时间。这一页还没有把那些时间轴和音频估计并排对比。

播放用的是延迟语料第 1 条（“店长，你来了。”），不是供应商合成的角色音。

同一次会话里录了屏。最长的一段大约 40 秒，是全身站在画面里的待机；另一段大约 28 秒，包含鼠标带动头部和一次播放。两段都是这台软件 WebGL 上的画面，帧耗时大约 100–180 ms。

## three-vrm 上碰到的限制

- 归一化骨骼的单位四元数对应 T 字。不播片段的话，站姿要自己转上臂，否则她会一直平举着手。
- `vrm.update` 会把归一化骨骼抄回原始骨骼，然后再跑 lookAt。自己转眼睛和头时要把 `lookAt.autoUpdate` 关掉，不然两套会抢。
- VRM 0 的口型预设名是 `a/i/u/e/o`，加载后映射成 `aa/ih/ou/ee/oh`。直接写旧名字不会驱动形状。
- VRM 0 的元数据是 `title` / `author`，VRM 1 才是 `name` / `authors`。
- 这页的口型估计是能量加三段频谱，不是音素对齐。全身镜头下张嘴幅度必须给足，否则看不清。
