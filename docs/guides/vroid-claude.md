# 克劳德 3D 模型制作规格（A8 外包用）

本文是交给 3D 建模方的**完整、自成一体的需求**。依据 `docs/05-art-brief.md` §1、A8，以及 `docs/01-product-and-realism.md` §5.2 整理。两者冲突时以 `05-art-brief.md` 为准。

随本文一起交付给建模方的参考图：`normal.png`（原作立绘，1152×2048，女仆装版）。

---

## 0. 一句话

把立绘里的女仆克劳德做成 **"打烊之后"的她**：摘掉女仆头饰、解下围裙、不穿披肩。成品是一个用于**实时对话表演**的全身 VRM 1.0 卡通模型。

模型的第一目标是**能演戏**：手、手臂、脸能自由做细腻的动作和表情。还原度排第二，两者冲突时，按 §3 的硬性约束取舍。

## 1. 角色

| 项 | 设定 |
|---|---|
| 年龄感 | 成年，20 岁出头。体态和脸都要读得出是成年人，**不要做成少女 / 幼态** |
| 身高 / 头身 | 约 160cm（含鞋），**6.5–7 头身** |
| 体型 | 纤细、端正。胸部适中偏小（要能抱臂，见 §3）。肩不要过窄，脖子不要过短 |
| 性格 / 气质 | 话少、一丝不苟、较真；平静、克制、礼貌。关键词：安静、端正、书卷气、温和但有原则 |
| 表演特征 | **情绪幅度很小**：高兴是嘴角一点笑，不高兴是变得更安静。所有表情形变都按小幅度做 |

**不得引入任何第三方作品的角色元素**：不要参考、混入或用任何已有作品的角色、发型模板或服装。如果用了生成式工具，提示词里不要出现任何作品名、角色名或画师名。

## 2. 造型（相对立绘的改编）

### 必须保留的识别特征

- 亮橘色长卷发
- 头部**右侧**（角色自己的右侧）一朵橘色菊花发饰，下面垂一个黑色小缎带
- 琥珀色眼睛
- 配色：米色为主，橘色和黑色为辅，少量金色点缀
- 高领，领口有黑色领巾和菊花胸针
- 菊花纹样贯穿全身（刺绣、胸针）

### 改编表

| 部位 | 立绘 | 3D 版 |
|---|---|---|
| 头饰 | 白色荷叶边女仆头饰 | **去掉**。菊花发饰和黑缎带保留 |
| 头发 | 及膝长卷发，发丝很碎 | **长度到腰**，保留卷度和体量感。发束**归并成少数几大股**（后发 4–6 股为宜），不要碎发丝 |
| 刘海 | 偏长，遮到眉眼 | 缩短或分开，**眉毛必须完整可见**。允许保留一两缕细发落在两眼之间（立绘特征），但不能挡住眉毛 |
| 耳饰 | 立绘里有小耳坠 | 可省略。保留的话要小，并且不做物理 |
| 披肩 | 盖住双肩的米色短披肩 | **去掉**；或改为不过肩线的小立领装饰 |
| 上衣 | 米色高领衬衫，胸前有荷叶褶 | 保留高领。胸前荷叶褶**压平**，做成贴图或很薄的一层，不能凸出 |
| 领巾 / 胸针 | 黑色领巾 + 菊花胸针 | 保留。领巾**短而贴身**，下端不过胸口，不做物理。胸针贴在领口，厚度尽量小 |
| 袖子 | 蓬松长袖 + 蕾丝前臂 + 荷叶袖口 | 上臂留**少量**泡泡袖；**前臂收窄、贴合**；袖口**止于手腕**，荷叶边很小或不做。蕾丝做成贴图 |
| 束腰 | 黑色束腰 + 金扣 + 细金链 | 保留黑色束腰和金扣。金链简化成贴图，或者去掉；**不做垂挂物理** |
| 围裙 | 白色荷叶边围裙 | **去掉** |
| 裙子 | 米 / 橘 / 黑多层及踝长裙 | **单层 A 字裙，长度到小腿中段**。用竖向拼色裙片保留米、橘、黑三色层次（主体米色，侧面或后面有黑、橘裙片，边缘一道细金线）。下摆小荷叶边可做成贴图。裙摆内侧要有正确的背面，或用双面材质 |
| 鞋 | 米色系带短靴 | 保留，鞋带做成贴图 |
| 书 | 双手抱在腰前 | 本次**不做**，以后作为独立道具另做 |

## 3. 硬性约束（高于还原度）

1. **双手完整露出**：五指清晰分开，袖口不过手腕
2. **能抱臂、能双手交叠放在身前**（她的习惯姿态）：胸前和上臂没有任何凸出的装饰
3. **会飘动的只有头发和裙摆**，外加发饰上的黑缎带（很短）。领巾、金链、耳饰都不做物理
4. **刘海不遮眉毛**：眉毛是表情的一半
5. **轮廓简洁**：剪影靠橘色长发加菊花发饰辨认，细节集中在上半身和脸

## 4. 技术规格（VRM 1.0）

| 项 | 要求 |
|---|---|
| 格式 | **VRM 1.0**（`.vrm`，不是 VRM 0.x），另附源文件（`.vroid` / `.blend` 等） |
| 面数 | 总三角面 **≤ 70,000** |
| 材质 | **MToon**，材质数 **≤ 8** |
| 贴图 | 每张 **≤ 2048×2048** |
| 骨骼 | VRM Humanoid 标准骨骼全套，**含全部手指骨**、upperChest、左右眼骨 |
| 初始姿态 | T-pose，面向 +Z（VRM 规范） |
| 视线 | 设置 LookAt。眼球转动范围自然，向上、下、左、右都不出现眼白异常或穿透眼眶 |
| 弹簧骨 | 头发、裙摆、发饰缎带。头发摆动要**沉稳**（她是安静的人），不要软弹 |
| 碰撞体 | 头、颈、胸 / 上胸、上臂、前臂、手、腰（hips）、大腿、小腿。目标：**头发不穿过手臂和裙子，裙摆不穿进腿** |
| Meta | 作者、许可等按负责人提供的信息填写；未提供时留空，不要编造 |

### 表情

**必做：VRM 标准预设全套**

- 情绪：`happy` / `angry` / `sad` / `relaxed` / `surprised`
- 口型：`aa` / `ih` / `ou` / `ee` / `oh`
- 眨眼：`blink` / `blinkLeft` / `blinkRight`
- 视线：`lookUp` / `lookDown` / `lookLeft` / `lookRight`

幅度要求：

- 情绪表情权重拉到 1.0 时也只是**小幅度**：`happy` 是眼睛微弯、嘴角上扬，不咧嘴；`angry` 是眉微压、嘴抿紧，不要怒目；`surprised` 是眼睛略睁大、嘴微张
- 口型要能和眨眼、情绪表情**叠加**而不破面

**能做则做（不能做就记入第二版，不卡交付）：自定义表情**

| 名称 | 要点 |
|---|---|
| `shy` | 脸红（腮红可用材质或贴图切换）、视线略移开、嘴抿着 |
| `troubled` | 眉头微蹙、眉尾下垂、嘴角略收 |
| `serious` | 眉微压、目光专注、嘴闭紧（纠正别人时的脸） |
| `thinking` | 视线上移或侧移、嘴微抿 |
| `curious` | 眼睛略睁大，嘴自然 |
| `sleepy` | 眼皮沉（半闭），其余端正 |

判断标准：**遮住下半张脸，只看眉眼，也能分辨出各个情绪。**

## 5. 验收标准

负责人或架构师按以下各条逐一检查。不达标的项，建模方须如实报告，不得修改测量方式。

1. 在 three-vrm 官方查看器中正常加载，识别为 VRM 1.0
2. 三角面 ≤ 70,000，材质 ≤ 8，贴图 ≤ 2048
3. Humanoid 骨骼齐全（含手指、upperChest、双眼）
4. 逐个把每个表情拉到 1.0：无破面、无穿模、无眼白外露；口型叠加眨眼时也正常
5. 三个姿势下**无严重穿模**：双手交叠于身前、抱臂、双手举过头顶
6. 播放走路或转身时，头发不穿过手臂和裙子，裙摆不穿进腿
7. 外观：
   - 和 `normal.png` 放在一起，一眼认得出是同一个人
   - 成年感明确
   - 眉毛完整可见
   - 双手干净露出
   - 发饰在头部右侧
   - 头发长度到腰

> 本节只发给建模方，不需要重复阅读正文。正文 §1–§6 的要求继续有效。本节按严重程度排序。
>
> 被评审文件：`claude_v1.vrm`（29,367,008 字节）、`claude_v1_report.md`、`screenshots/`。
> 评审方式：直接解析 `.vrm`（glTF JSON、蒙皮权重、形变目标、SpringBone），逐张核对截图。下文所有数字都是从文件里实测的，不是从报告里抄的。

### 结论

**v1 不通过。** 硬指标全部达标：VRM 1.0、49,871 三角面、3 个材质、贴图 2048、55 根 Humanoid 骨骼、17 个标准表情，造型方向也对。不通过的原因是**表演能力**：手和脸不能用，物理只有一半在起作用，报告里有几条结论和文件不一致。

本次修订是**最后一次修订机会**。v2 如果仍有任一 P0 项不达标，负责人将改用 VRoid Studio 重建底模。

### P0：必须修复

**P0-1 手部重做**

现状：
- 手是独立网格 `Five_Finger_Hands_Mesh`，752 个顶点、1,400 个三角面。
- 每根手指是一根圆柱，和手掌分离、有缝（见 `09_hand_detail.png`）。
- 手腕和袖口之间是硬拼接。

要求：
- 手按成年女性手的比例建模，手掌和手指是连续的网格；有指关节的弯折处，有指甲（可以只画在贴图上）。
- 手腕和袖口衔接自然。手和前臂可以是两块网格，但握拳、张开、手腕弯 60° 时不能出现缝隙。
- 每根手指 3 节骨骼的权重都要正确。弯到 90° 时关节处不塌陷、不穿插。
- 手部面数控制在**每只 1,500–3,000 三角面**，总面数仍然 ≤ 70,000。

验收证据（**必须在 three-vrm 里截图**，不接受 Blender 渲染）：
- 张开手掌（正面、背面各一张）
- 握拳
- 食指竖起，其余四指握起
- 掌心向上做示意的手势

**P0-2 面部表情和视线要真正可见**

现状：
- 底模的眉、眼、嘴都画在贴图上，表情只是轻推表面顶点。实测最大位移：happy 2.6mm，sad 1.5mm，angry 3.9mm，surprised 4.5mm，relaxed 11.5mm。
- `07_expressions.jpg` 里各情绪基本分不出来。
- 视线是靠 `eye.L` / `eye.R` 骨骼带动约 300 个皮肤顶点：画上去的眼睛和周围皮肤一起扭，眼球本身不转。
- 嘴内网格是一块 24 个三角面、深度为 0 的平片。

要求：
- **眼睛**：做独立的眼球（或虹膜）几何体，放进眼窝。视线骨骼只旋转这部分几何体，不再带动皮肤。眼白和虹膜在视线左右上下转到极限时都不能穿出眼眶。
- **眉毛**：做成独立几何体，或贴在额头上的浮面。眉毛要能单独上抬、下压、皱起，形变幅度在 3–6mm 量级，在半身构图里肉眼清楚可见。
- **眼睑**：眨眼要完全闭合，不露缝、不破面。半闭（为 `sleepy` 预留）也不能变形。
- **嘴**：口型要有可见的开合和形状差异。`aa` 张口的深度要能看到嘴内，嘴内要有一定深度（口腔、牙齿可以简化）。
- 各表情幅度仍然遵守"小幅度"原则，但必须**可分辨**。验收方法：遮住下半张脸，只看眉眼，能分辨出 happy / angry / sad / relaxed / surprised。
- 情绪表情如果包含闭眼或眯眼，把 `overrideBlink` 设为 `block` 或 `blend`，避免和眨眼叠加时破面。

如果在 Tripo 底模上做不到上面这些，请在报告里直接写"做不到"并说明原因，**不要交付一个形变量很小的版本**。

验收证据（three-vrm 截图，半身构图，同一机位）：
- 17 个标准表情各一张，权重 1.0
- 叠加组合：`aa + blink`、`happy + blink`、`surprised + lookLeft`
- 视线 `lookUp` / `lookDown` / `lookLeft` / `lookRight` 各一张，附眼部特写

**P0-3 碰撞体挂接错误**

现状：
- 文件里定义了 15 个碰撞体，但唯一的碰撞组 `Head_Body_Arms_Legs` 只包含 8 个（索引 4, 8–14）。
- 未生效的 7 个：head、neck、chest、upperChest、upper_arm.R、lower_arm.L、lower_arm.R。
- 报告写的"碰撞体覆盖头、颈、胸、上胸、双臂……"与文件不符。

要求：
- 所有碰撞体都要进入对应的碰撞组。
- 头发链要能碰到 head、neck、chest、upperChest、双上臂、双前臂、hips。
- 裙摆链要能碰到 hips、双大腿、双小腿。
- 可以按需拆分成头发组和裙摆组。
- 上臂和前臂建议改用胶囊体（capsule），覆盖整段骨骼；单个球体覆盖不全。

**P0-4 两侧头发没有绑定**

现状：
- `hair.side.L` 和 `hair.side.R` 两条弹簧骨链上，没有任何顶点绑定。
- 后发三条链合计约 3,000 个主导顶点，其余头发都刚性绑在 head、upperChest 等骨骼上。

要求：
- 肩前的两股侧发要刷到侧发链上，并能随动作摆动。
- 后发里长到腰部的部分，也要交给后发链控制，不能刚性跟着身体。
- 报告里列出每条弹簧骨链绑定了多少个顶点。

**P0-5 姿势测试按要求重做**

现状：
- `05_folded_arms.png` 是双手叠在胸前，**不是抱臂**。
- 三个姿势都是 Blender 渲染，不是 three-vrm。
- 走路测试没有做。

要求（全部在 **three-vrm** 里、Spring Bone 开启的状态下截图）：

| 姿势 | 定义 | 截图角度 |
|---|---|---|
| 双手交叠于身前 | 双手在小腹前方，一只手的掌心盖在另一只手的手背上，手肘贴近身体 | 正面、3/4 侧面 |
| 抱臂 | 两条前臂在胸前交叉，每只手托住或抓住另一侧的上臂 | 正面、3/4 侧面、侧面 |
| 双手举过头顶 | 两条手臂竖直上举，手掌在头顶上方 | 正面、背面 |
| 走路 | 至少 2 个完整步态循环（可以用任意公开的 VRMA 或 Mixamo 走路动画） | 正面、侧面，各截 3 帧，或者交一段短视频 |

每张截图都要能看清楚：头发和手臂、头发和裙子、裙摆和腿之间有没有穿插。有穿模就如实标注出来。

**P0-6 在 three-vrm 里颜色失真**

现状：
- 在 three-vrm 预览中（`01_front`、`03_back`），黑色束腰和黑色裙片显示为中灰色，整体颜色发白、对比度低。
- 裙子上有条纹状的瑕疵。
- Blender 渲染里的颜色和 three-vrm 里差别很大。

要求：
- 检查 MToon 的 shade color、主贴图的色彩空间（sRGB）、法线贴图的设置，以及 shading toony / shift 参数。
- 修完后在 three-vrm 默认光照下，各部位颜色要接近正文 §2 的参考色。黑色部分要读得出是黑色，明度和 `#3E3E3E` 相近。
- 条纹瑕疵要消除。如果是法线贴图造成的，可以去掉法线贴图；卡通渲染不需要它。

### P1：必须修复，但不影响能否演戏

**P1-1 Meta 信息**
