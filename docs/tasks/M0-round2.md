第一轮的结果见 PR #1、#2 和三份报告（`evals/latency/REPORT.md`、`evals/tts/REPORT.md`、`apps/web/M0_REPORT.md`）。M0 的三个问题都还没有答案：

| 问题 | 现状 | 卡在哪 |
|---|---|---|
| 级联链路能否 P50 ≤ 800ms | 没有国内数据。俄勒冈的 6.8s 含跨境往返，不能用 | 供应商商品没开通、账号受限 |
| 断句能否守住误抢话 ≤ 5% | 固定 500ms 在长句上 5/5 误抢话；标点模型 15/20 提前截断 | 缺专门的话轮检测模型 |
| VRM 在真机上是否达标 | 只有云主机软件渲染的 9fps，真机没测 | 没在笔记本和手机上打开过 |

## R2 国内级联实测（Cursor，等 R0）

就是第一轮 D1 的全量，在上海服务器上跑：

1. **先 smoke**：每家打一次，全部通过再进入全量。有不通的，报告里写明，只跑通了的组合
2. **全量**：至少 2×2×2 组合，20 条 × 3 遍。断句用 R3 选出的最好方案和固定 500ms 各跑一次
3. **限流**：并发 1，请求间隔可配置。遇到 429 退避后重试，连续失败就停，不要把账号打进限流
4. **往返延迟**：报告附服务器到每家接入点的 RTT（`curl -w` 的 connect / TLS / 首字节）
5. **TTS 首包与试听**：豆包开通后补上 D2 的豆包一列 14 条；CosyVoice 一列用 `cosyvoice-v3.5-flash` 重新合成 14 条，旧的 v3-flash 音频移到 `out/dashscope-v3/` 留作对照。试听页三家齐全，列标题注明型号
6. **快脑型号**：通义一侧用 `qwen3.8-flash`。报告里每个组合都写明实际调用的型号 ID

**验收**同第一轮 D1。达不到 800ms 照实写，并指出瓶颈在哪一环。

## R3 话轮检测（Cursor，不需要供应商密钥）

第一轮证明了两件事：固定静音阈值守不住句中长停顿；标点恢复模型会给半句话补句号，不能当话轮检测用。这一轮比较专门的话轮检测方案。

**候选**（可补充）：

- 音频类：Pipecat 的 Smart Turn（开源，多语种）
- 文本类：LiveKit Agents 的多语种 turn detector、TEN Turn Detection（开源，支持中文）
- 供应商自带：豆包流式识别和 Paraformer 的服务端断句参数（等 R0，开通后补测）

**方法**：

1. 文本类模型的输入改用**真实 ASR 的流式中间结果**，不再用理想文本。R0 之前可以先用本地 SenseVoice / FunASR 出中间结果
2. 组合策略也要测：例如"静音 ≥ 200ms 时问模型，模型判没说完就继续等，静音 ≥ 1200ms 强制结束"
3. 扩充长句语料：现有 5 条不够判 5%，补到至少 20 条带句中停顿的句子（停顿 400–1000ms，位置放在逗号、"然后"、"就是"这类连接词后）

**交付**：`evals/latency/REPORT.md` 增加话轮检测一节，每个方案报误抢话率、提前截断率、端点滞后 P50 / P95、单次推理耗时（CPU），以及推荐方案。

**验收**：误抢话率 ≤ 5% 的方案里选端点滞后最低的；没有方案达标就照实写。

## R4 形象真机验证（Cursor 部署，负责人测）

1. **部署**：把 D3 demo 构建后放到测试服务器上，负责人用笔记本和手机直接打开。D3 不用麦克风，备案下来之前用 IP 加 HTTP 访问即可。模型文件走服务器下载，不入库
2. **性能面板**：页面上显示 GPU 名称（`WEBGL_debug_renderer_info`）、帧率、帧耗时，方便负责人截图回报
3. **时间戳口型**：用 D2 里 MiniMax 和 CosyVoice 的字级时间戳（CosyVoice 以 v3.5-flash 重新合成后的为准）做时间轴驱动口型（汉字转拼音再映射到 5 元音），与音频驱动版并排切换对比
4. **VRM 1.0**：示例模型是 VRM 0.x。负责人的 VRoid 模型导出时选 VRM 1.0，到了就替换测试

**负责人要回报的**：笔记本和手机各一张性能面板截图；看 60 秒待机有没有循环感；两种口型哪种更自然。

**验收**同第一轮 D3。
