## R3 话轮检测（Cursor，不需要供应商密钥）

第一轮证明了两件事：固定静音阈值守不住句中长停顿；标点恢复模型会给半句话补句号，不能当话轮检测用。这一轮比较专门的话轮检测方案。

**候选**（可补充）：

- 音频类：Pipecat 的 Smart Turn（开源，多语种）
- 文本类：LiveKit Agents 的多语种 turn detector、TEN Turn Detection（开源，支持中文）
- 供应商自带：豆包流式识别和 Paraformer 的服务端断句参数（等 R0，开通后补测）

**方法**：

1. 文本类模型的输入改用**真实 ASR 的流式中间结果**，不再用理想文本。R0 之前可以先用本地 SenseVoice / FunASR 出中间结果
2. 组合策略也要测：例如"静音 ≥ 200ms 时问模型，模型判没说完就继续等，静音 ≥ 1200ms 强制结束"
3. 扩充长句语料：现有 5 条不够判 5%，补到至少 20 条带句中停顿的句子（停顿 400–1000ms，位置放在逗号、"然后"、"就是"这类连接词后）

**交付**：`evals/latency/REPORT.md` 增加话轮检测一节，每个方案报误抢话率、提前截断率、端点滞后 P50 / P95、单次推理耗时（CPU），以及推荐方案。

**验收**：误抢话率 ≤ 5% 的方案里选端点滞后最低的；没有方案达标就照实写。

# R2 评审（2026-11-18）

**结论：R2 验收通过。** 12 组 × 20 条 × 3 遍齐全，型号写实，瓶颈如实指出。第二种断句没跑，原因成立（R3 未出方案）。

## 延迟拆解

最快组：豆包识别 + `qwen3.8-flash` + MiniMax `speech-2.8-turbo`，端到端 P50 1712ms，P95 2240ms。按说完话之后的时间顺序：

| 段 | P50 | 说明 |
|---|---:|---|
| 断句 | 500ms | 固定阈值，R3 的目标是 200–300ms |
| 等 ASR 定稿 | ~160ms | ASR 定稿在说完后 664ms，比断句晚约 160ms。测量脚本在断句后等定稿才调 LLM（`pipeline.py` 最多等 3 秒） |
| LLM 首 token | 689ms | 每次调用新建 `httpx.AsyncClient`，含一次 TCP + TLS 握手（到百炼约 60–90ms） |
| 首子句 | 39ms | |
| TTS 首包 | 192ms | 合成已经够快 |

三处可以工程化消掉：断句从 500ms 降到约 250ms；断句时直接用最新的中间结果调 LLM，不等定稿；LLM 连接复用。全部做到，估算 P50 在 1000ms 上下，**仍然高于 800ms**，剩下的主要是 LLM 首 token。所以 800ms 只靠串行优化达不到，需要 R6 的"提前开口"或更快的快脑（R5）。

**暂不改架构。** R5、R6 做完后，如果最好的实测 P50 仍高于 1000ms，再评估端到端语音模型（或者用端到端模型做"嘴"、级联做"脑"的混合方案）。

## 其他发现

- **CosyVoice v3.5-flash 没有系统音色**，只能用复刻音色或设计音色。v3-flash 的结果有效，保留。要不要用"声音设计"给克劳德做专属声线，由负责人决定，见 R7
- **DeepSeek-V4.1-Flash 首 token 比 `qwen3.8-flash` 慢 500ms 以上**，不进 M1 候选。方舟上的豆包低延迟档这轮没测到，R5 补
- **报告开头的"测试环境"表还写着俄勒冈**，和后文的上海全量矛盾，R1 一并修
- **R1、R3、R4 还没做**，优先级不变

## R5 快脑首 token 专项（Cursor）

只测 LLM，不接音频，便宜又快，目的是找出首 token 最低的快脑。

1. **连接复用**：长连接、预热一次再计时，记录首 token 的 P50 / P95，并和"每次新建连接"对比
2. **候选**：`qwen3.8-flash`（基准）；方舟上负责人开通的豆包低延迟档；另外至少挑 2 家国内低延迟档模型，选择理由写进报告。和服务器同在腾讯云的混元低延迟档值得一测
3. **条件一致**：同一份人设提示词（约 1500 字）加 4 轮历史，开提示词缓存，关闭思考，`max_tokens` 80，每个模型 50 次，并发 1
4. **角色稳定性**：每个模型另存 10 条回复原文，供架构师判断口吻（有没有变回助手腔）

**交付**：`evals/latency/REPORT.md` 增加"快脑首 token"一节：首 token P50 / P95、有无连接复用的差值、每百万 token 价格、10 条回复样例的路径。

## R6 提前开口（Cursor，等 R3 出断句方案）

把串行链路改成重叠执行，在 `evals/latency` 里实现并实测：

1. **用中间结果起跑**：断句一判定就用 ASR 最新中间结果调 LLM，不等定稿。定稿和中间结果不一致时的处理要写明（文本相同就继续；差异大就作废重来），并统计作废率
2. **推测式生成**：静音达到约 150ms、话轮检测模型给出"大概率说完"时就先调 LLM；用户接着说就取消。统计浪费的调用比例
3. **连接复用**：LLM、TTS 的连接在会话开始时建立并保活

**交付**：用最快的一组供应商组合，对比"串行"和"重叠"两种链路的端到端 P50 / P95、作废率和多出来的调用量。

**验收**：数字如实写。重叠版 P50 ≤ 800ms 就过；达不到，写明还差在哪一段。
