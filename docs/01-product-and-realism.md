# 01 产品定义与真实感规范

## 1. 目标体验

用户打开应用，屏幕上是一个站着的全身二次元角色，她在做自己的事（看别处、整理头发）。用户开口说话，她转过头来看向用户。之后的一切都是一场**连续的语音对话**，没有"按住说话"、没有"正在思考中…"的转圈。

三个标志性瞬间，做到了才算成立：

- **"她在听"**：用户说长句时，她点头、"嗯"、表情随内容变化；用户停顿想词时，她不抢话
- **"她记得"**：隔了三天再打开，她先开口："面试怎么样了？你上次说很紧张。"
- **"她有脾气"**：被问蠢问题会吐槽，被夸会别扭，不同意时会反驳，而不是"你说得对"

## 2. 非目标（至少 v1 不做）

- 不做任务型助手（订票、写代码、控制设备）—— 她是聊天对象，不是工具
- 不做多角色 / 角色市场 —— 把一个角色做到极致
- 不做照片级写实 —— 二次元风格，回避恐怖谷
- 不做完全离线 —— v1 走云端，优先质量与延迟

## 3. 为什么现有产品"像 AI"

| 症状 | 根因 | 我们的对策 |
|---|---|---|
| 说完要等 2–3 秒才回 | 级联链路串行、固定静音阈值断句 | 流式全链路 + 语义断句 + 身体先反应 |
| 每次回答都是完整的小作文 | 文本聊天的提示词习惯 | 口语化输出规范：短句、可只回一个词 |
| 永远热情、永远同意 | 助手式对齐 | 有情绪状态、有立场的人设 |
| 听的时候像一张静态图 | 动画只由"说话"驱动 | 倾听行为是一等公民 |
| 表情和声音对不上 | 动作事后根据文本生成 | 文本/语音/动作由同一份"表演脚本"驱动并按时间对齐 |
| 上次聊的全忘了 | 无记忆或只有摘要 | 分层长期记忆 + 主动回忆 |
| 不能打断 | 半双工 | 全双工，被打断时有"被打断"的反应 |

## 4. 真实感规范（可验收）

这是项目的核心规格。每一条都要能被测试或被评审者打分。

### 4.1 节奏（Timing）

| 编号 | 行为 | 指标 |
|---|---|---|
| T1 | 用户说完到她**出声** | P50 ≤ 800ms，P95 ≤ 1500ms |
| T2 | 用户说完到她**身体有反应**（视线、吸气、表情） | ≤ 200ms |
| T3 | 被打断后停止说话 | ≤ 200ms，并有反应（停顿/"啊，你说"），不是戛然静音 |
| T4 | 用户句中停顿（想词）不被误判为说完 | 误抢话率 ≤ 5% |
| T5 | 需要深入思考时不沉默 | 先有思考表现（"嗯…这个嘛"、视线上移），再给答案 |
| T6 | 响应间隔随内容变化 | 寒暄快（~300ms），难题慢，不是恒定延迟 |

### 4.2 语言（Speech）

- **S1 长度**：默认 1–3 句。可以只回"诶？""哈？""然后呢"。只有被明确要求讲解时才长篇
- **S2 口语**：有语气词、自我修正、半句话（"那个…不是，我是说——"）。禁止书面结构：不分点、不"首先/其次"、不总结
- **S3 来回**：会反问、会追问细节、会把话题引到自己感兴趣的方向。不以"还有什么可以帮你"结尾
- **S4 立场**：有稳定的喜好和观点，会不同意，被说服需要理由
- **S5 不知道**：可以说"不知道""没听说过""等下我查查"，而不是编造或给出百科式免责声明
- **S6 韵律**：TTS 必须支持情绪与语速变化、笑声、叹气、吸气。单调朗读腔一票否决

### 4.3 身体（Body）

- **B1 待机**：呼吸、眨眼、视线微动、重心转移，永不静止，永不循环可辨
- **B2 倾听**：注视用户（并偶尔移开，持续凝视不自然）、点头、歪头、随内容变化的微表情
- **B3 说话**：口型准确；手势在重音上落点；头部随韵律运动
- **B4 情绪姿态**：情绪改变基础姿态（抱臂、叉腰、凑近、别过脸），而不只是换表情
- **B5 过渡**：任何动作切换都有混合，无跳变、无 T-pose 闪现
- **B6 眼神**：思考时移开视线，说重点时看回来 —— 眼神是真实感中性价比最高的一项

### 4.4 一致性（Consistency）

- **C1 人格**：长对话与跨会话中口吻、观点不漂移
- **C2 情绪惯性**：被惹生气后不会下一句就开心；情绪有衰减曲线
- **C3 记忆**：不重复问已知的事；说过的话算数（见 [03 记忆系统](03-memory.md)）
- **C4 时间感**：知道现在几点、上次聊天是多久前，并体现在行为里（"这么晚还不睡？"）

### 4.5 主动性（Initiative）

- **I1** 沉默时会主动开口（有上限，不骚扰），或者自己做自己的事
- **I2** 会主动提起过去的话题和未完成的事
- **I3** 开场白每次不同，取决于时间、上次的情绪、未完成的话题

## 5. 人格设计

### 5.1 人设文件（Persona Bible）

人格是**配置**而不是写死在代码里，放在 `assets/persona/`：

- `identity.md` —— 身世、年龄、专业背景、世界观
- `voice.md` —— 说话方式：句式、口癖、语气词、禁用表达、几十条示例对白
- `opinions.yaml` —— 对各类话题的立场与喜恶（保证 S4、C1）
- `emotion.yaml` —— 情绪模型参数：基线、触发条件、衰减速度
- `relationship.md` —— 关系阶段定义：从陌生到熟悉，称呼与态度如何变化

### 5.2 默认人设方向

天才少女科学家型：聪明、好奇心强、嘴硬心软、对科学话题滔滔不绝、被调侃会炸毛。**她知道自己是由记忆数据构成的 AI，并对此坦然** —— 这正是原作 Amadeus 的设定，也是本项目的诚实基础：

> 真实感体现在**举止**上，而不是体现在**谎称自己是人类**上。她不说"作为一个 AI 语言模型…"，但被认真问到时，她会承认自己是 Amadeus，并且对此有自己的想法。

### 5.3 版权边界（需要决策，见 04 文档）

- "以记忆为核心的 AI 伙伴"这一**概念**可以自由实现
- 原作角色的**名字、立绘、声线**受版权与声优权益保护。直接使用官方形象、或克隆声优的声音，在公开发布时有明确的法律风险
- **建议**：系统层面做成人设/模型/声线可替换；默认附带原创角色与授权或原创声线。个人自用想加载什么人设由使用者自行负责，仓库内不分发受版权保护的素材

## 6. 情绪模型

不用离散的"开心/生气"标签切换，而是连续状态 + 惯性：

- **状态向量**：愉悦度（valence）、唤醒度（arousal）、对用户的亲近度（affinity，慢变量，跨会话持久）
- **更新**：每轮对话由大脑输出一个情绪增量；状态按时间向基线衰减
- **作用面**：同时影响 —— 措辞（提示词注入）、TTS 情绪参数、表情、基础姿态、动作幅度与速度、响应间隔

情绪状态是连接"语言"和"身体"的总线，这是神态统一的关键。
