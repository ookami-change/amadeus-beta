## 当前阶段

**M0 收尾 → M1**。第三轮任务单与评审见 [`tasks/M0-round3.md`](tasks/M0-round3.md)。负责人 2026-11-21 决定：延迟和话轮检测先放宽标准推进。M1 临时目标：误抢话 ≤ 10%、端到端 P50 ≤ 1200ms、P95 ≤ 3000ms；最终目标 800ms / 5% 不变。

M0 要回答的三个问题：

| 问题 | 现状 |
|---|---|
| 说完到开口能否 P50 ≤ 800ms | 未达标。R6b 在真人录音上同场实测：「提前起跑、等断句再播」误抢话 5/50，P50 1422ms、P95 2277ms，比串行（2292 / 3204）快约 0.9 秒；R6 的「准备好就播」P50 1279ms，但误抢话 11/50。等断句再播时 P50 的下限就是断句点（约 1400ms），要到 1200 得先有更早又不抢话的断句 |
| 断句能否误抢话 ≤ 5% | 真人录音上只有 2000ms 达标（2/50）。R3c：≤ 10% 档没有组合明显好过固定静音，M1 用自适应静音「短 1400 / 长 1800」，4/50，滞后 P50 1396ms；LiveKit 文本模型能以 2/50 把三成多轮次提前到约 1.2 秒（均值 1618ms），但阈值是在这 50 条上挑的，只作候选。剩下的误抢话都是「话已完整、停顿后再补一句」，要靠打断后让话来兜 |
| VRM 在真机上是否达标 | 笔记本只有一份自动化浏览器里的数（M4 Pro 中位约 30fps，可能被限帧），手机未测。等 R4a 测量页上线后负责人在真机上测，以及 Kimi 的克劳德模型 |
